One live run, step by step

GitHub Actions runs python -m event_prediction.predict every hour at :07 UTC (+ a 22:37 backup). Nothing is issued before 22:00 UTC; the first run after that writes predictions/<date>/predictions.json and commits it.

The decision maths

For a market priced p with N days to its deadline, assume a constant daily hazard and choose the date with the best expected judge score.

λ        = 1 − (1 − p)^(1/N)                       # implied daily hazard
P(X = k) = (1 − λ)^(k−1) · λ,   k = 1..N              # first-occurrence day
credit   = [10, 8.5, 6.5, 6.5, 4.5, 4.5, 4.5, 4.5]    # |offset| 0..7 days, else 0
E(d)     = 0.9 · Σ_k P(X = k) · credit[|k − d|]      # 0.9 = strict-judge haircut
d*       = argmax_d E(d),  d ∈ [1, min(N, 7)]
issue if E(d*) ≥ 3.5   (every prediction costs 3)    # "on <date>" markets: d = N, E = 9·p

Code: poly/strategy.py → first_occurrence_probs, best_date; live use in poly/live.py:signals and poly/manifold.py:live_signals.

Rules the data must obey

  • Only data timestamped before the prediction: every feature is point-in-time (wallet stats via merge_asof on resolution time; trade windows strictly before τ).
  • GDELT live uses the v1 daily file for the previous day (cutoff = issue day − 1); v2 15-minute counts are ~2.2× smaller and would shift features.
  • Time splits everywhere: LightGBM train ≤ 2024-06-30, val ≤ 2025-06-30, test after. Insider val from 2025-10-01, test from 2026-04-01.
  • Secrets (Anthropic key / Claude OAuth token) live only in GitHub Actions secrets and your shell, never in the repo.
